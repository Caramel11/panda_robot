# 0630thesis 写作语言风格规范

本文后续修改应采用控制科学与工程硕士学位论文的正式写法，在语言上保持严谨、克制、连续和可验证。整体风格可参考《非接触人机交互场景下基于微分博弈的协同控制策略研究》的行文方式：先说明工程背景和控制问题，再给出数学建模、假设、定义、控制器设计、理论分析和实验验证。段落之间依靠研究对象和变量关系自然推进，少依赖显眼的逻辑标记。正文不追求口号化表达，也不追求密集分点，而应让读者顺着模型、公式和实验现象理解方法。

当前论文已有较好的技术写作基础。比较突出的优点是能够把控制变量的数学含义和物理含义联系起来，能够在公式后解释状态、误差、权重和安全裕度对应的实际任务现象，也能在实验分析中同时讨论轨迹误差、接触力误差、几何约束误差和操作者负担。这种写法应继续保留。后续需要收敛的是表达方式：减少过度解释式的对照句，减少“问题清单式”的段落，减少引号、破折号和括号中补充说明的使用，使文字更像自然形成的研究叙述，而不是由提示词展开的答案。

模范论文的主要语言特征可以概括为“平实、顺序清楚、证明和实验各司其职”。绪论部分通常先介绍应用背景，再说明现有方法的不足，随后引出本文研究内容。方法章节开头会用一两个自然段交代本章研究问题，再进入定义和假设。理论分析部分多使用“根据”“由”“因此”“可得”等数学推导用语，句子围绕公式前后关系展开。实验部分一般先说明平台、参数和评价指标，再描述图表结果，最后把现象回扣到理论结论或方法动机。全文很少使用强烈转折式句子，也较少把每个观点拆成大量并列条目。

本文应形成的个人写作风格是：问题意识明确，表达不过度炫技；公式推导严谨，物理解释跟得上；实验分析客观，不把单项指标解释成全面胜利。每个章节开头应回答本章为什么存在，但不宜写成宣传式摘要。每个公式出现后，应说明其中关键符号的含义，并解释该公式服务于哪个控制目标。每个实验图表出现前，应交代实验设置和预期观察对象；图表之后，应结合数据说明现象，而不是只重复图题。

论文正文应尽量采用中等长度段落。一个自然段通常围绕一个中心问题展开，长度以 5 到 10 行为宜。只有在列出贡献、实验分组、算法步骤或假设条件时，才使用分点。普通解释性内容不要频繁写成“第一、第二、第三”的形式，也不要连续多段都以“首先、其次、最后”开头。章节小结可以适度概括，但不宜把前文每个小节机械复述一遍，应重点说明本章解决了什么问题、得到什么结论、如何引出下一章。

控制科学论文中的判断语气应当稳健。实验结果可以写“结果表明”“可以看出”“说明该方法在该工况下具有更好的综合表现”。不宜写“显著优于所有方法”“全面证明了方法最优”“彻底解决”等绝对化表述，除非已有统计检验、理论证明或严格实验边界。对基线方法的评价也应保持客观，可以指出其适用条件和局限，避免把对比方法写成明显薄弱的陪衬。

为降低人工智能生成特征，后续改写需要特别控制若干句式。以下表格作为全文检查规则使用。

| 容易显得生硬的写法 | 建议改写方向 |
| --- | --- |
| 频繁使用“并非 A，而是 B”一类强对照句 | 直接说明 A 的局限，再自然引出 B 的作用 |
| 多段连续使用“第一、第二、第三” | 只在贡献、实验分组和步骤中使用；一般论述改为连续段落 |
| 频繁使用“换句话说”“需要强调的是” | 改为具体解释变量、指标或实验现象本身 |
| 大量使用引号标注概念 | 首次定义时保留，后文直接使用中文术语 |
| 频繁用破折号解释概念 | 改为逗号、分号或独立句 |
| 每段都先给结论再解释 | 根据背景、模型、结果的自然顺序展开 |

术语写法应统一、克制。中文术语首次出现时可附英文全称，后文使用中文名称。对于“帕累托最优”“远心运动”“阻抗控制”“微分博弈”等固定学术术语，不需要反复加引号。变量名应在正文中给出定义，随后保持唯一含义。例如，`\alpha_{\mathrm{HR}}` 只表示人机监督权重，`\alpha_{\mathrm{FP}}` 只表示力位优先级，`\rho_F` 只表示接触力安全裕度。若变量跨章节复用，章节开头应简短提醒其物理含义，避免读者把不同层级的权重混为一谈。

理论分析部分应遵循控制学科的常见写法。假设用于限定系统、输入、扰动和参数变化范围，不应写成泛泛的工程条件。定义用于固定概念和指标，例如误差、可行集、安全裕度和性能指标。引理解决证明中间环节，定理给出主要性质，证明应围绕已有公式逐步展开。若理论条件偏保守，应在定理后用“注”说明保守性和工程取值，不宜在正文中反复解释同一件事。

实验分析部分应坚持“设置清楚、指标可测、结论有边界”。描述实验平台时，应说明硬件、任务、传感量、控制频率和重复次数。描述评价指标时，应说明指标的数学定义、物理意义以及为什么选用该指标。分析结果时，应先写主要现象，再结合数值解释原因，最后说明该现象支撑了哪个方法设计。若某一方法在单项指标上不是最优，可以如实说明，并解释本文方法追求的是力安全、轨迹精度、人类修正和实时性的综合折中。

后续全文修改时，可以采用以下段落节奏。绪论和研究现状采用“背景现象、代表性方法、局限、本文切入点”的顺序。方法章采用“任务目标、模型建立、控制律设计、参数含义、理论性质”的顺序。实验章采用“平台和工况、对比方法、指标定义、图表结果、综合分析”的顺序。小结采用“本章工作、主要结论、与下一章关系”的顺序。这样的节奏符合控制科学研究生论文规范，也能避免散文化或报告式堆砌。

在正式改写前，可按以下标准快速自检：一页内是否出现多次强对照句；是否连续三段都在分点；是否用引号标出本应自然融入正文的普通术语；是否出现没有定义的数学符号；是否把单次实验现象写成普遍结论；是否在正文中提到代码文件、数据目录或脚本名称；是否只给结论而没有说明对应指标。若存在这些问题，应优先改写段落结构，再处理局部用词。

本文最终应呈现的语言面貌是：读起来像一篇由研究者长期调试系统后写出的控制论文。文字承认工程限制，重视变量定义，关注实验条件，结论有依据、有边界。这样的风格既贴近模范论文的硕士学位论文规范，也能保留本文自身在机器人柔性接触、人机协同和合作博弈控制方面的研究特点。

## 历史修改要求补充

后续正式改稿还应遵守已经反复确认过的具体写作约束。这些约束主要用于降低人工生成痕迹，保证论文像长期实验和推导后自然形成的硕士学位论文。

标题应保持一个核心关键词，并在关键词前后加入适度修饰形成短语。二级标题和三级标题不要把两个概念并列堆在一起，例如“建模与控制”“仿真与实验”这类并列题名应谨慎使用。标题长短可以错落，但每个标题应能让读者一眼判断该小节的中心任务。参考模范论文的写法，标题宜有研究对象、方法属性或问题边界，避免直接写成口号式短词。

段落承接应依靠研究对象、变量关系和实验现象自然推进。不要把“首先从……说起”“需要指出的是”“还需要说明的是”之类承上启下句单独成段。每段首句不宜过短，也不宜机械地先抛结论；应在体现中心意思的同时保持长短句交错。普通叙述尽量采用正向逻辑，少用“不在于……而在于……”“不是……而是……”“并不……也不……”等强对照句式。

绪论和背景章节应少给具体公式。第一章主要负责建立研究对象、应用场景、方法动机和章节关系，涉及基础知识的公式可放到第二章，涉及方法细节的公式放到对应方法章。第一章中可以给出应用场景图、技术路线图和章节关系图，但不宜提前引入后续章节的专用符号。

符号和术语必须先定义再使用。所有数学符号，包括相关系数、均方根误差、滤波系数、仲裁参数和安全裕度，都应在正文中说明数学含义和物理意义。`\alpha_{\mathrm{FP}}` 只表示力位优先级，`\alpha_{\mathrm{HR}}` 只表示人机仲裁权重，`\rho_F` 只表示接触力安全裕度。方法名称和实验组名称应尽量使用简短中文代号，例如“强位置优先”“均衡优先”“强力优先”，避免在正文中直接使用代码式英文名称。

中文正文中尽量不用斜杠式名词。类似“混合位置/力控制”“MPC/QP”“切向/法向”等表达，在正式正文中应根据语境改为“力位混合控制”“MPC 或 QP”“切向和法向”。固定英文术语首次出现时采用“中文名称（英文名称）”形式，后文使用中文名称。必要英文缩写可以保留，但不要在一句话中堆叠多个英文缩写。

图表应嵌入叙事，而不是作为结果堆叠。每张图表前先用一小段说明实验内容、变量设置和预期观察对象；图表后再结合数据解释现象，并回扣方法设计。图题应具体描述工况和指标，避免写成“某章实验结果”或“参数设置”这类泛标题。插图排版应保证页面紧凑，减少因浮动体造成的大段空白，也不要为了节省空间把多个不相关图塞进同一幅图。

正文不要出现代码目录、脚本名称、原始数据文件名或生成过程说明。实验数据来源可以写成“实验系统记录了接触力、末端位姿、仲裁参数和控制输入”，绘图来源可以写成“根据同一时间窗内的实验记录统计得到”。论文应呈现实验系统和数据结论，不呈现代码执行过程。

理论模块的使用应服务于论证。定义用于固定研究对象，假设用于限定可分析范围，引理用于连接推导环节，定理用于给出本章核心性质，注用于解释保守性和工程取值。普通实现细节、变量说明和显然成立的限幅关系不宜包装成过大的定理。证明中保留必要数学关系和条件调用，物理解释放在定理前后的正文中。

实验结论应有明确边界。可以写“在所设置工况下”“结果表明”“说明该方法具有较好的综合表现”，不要写“全面优于”“彻底解决”“严格保证所有安全约束”等超出证据范围的判断。若某个基线在单项指标上更好，应如实说明，并解释本文方法关注的综合折中。

## 形式化模块的使用方式

模范论文中，定义、假设、引理、定理、证明和注并不是为了增加理论感而机械插入，而是按照论证需要逐层出现。第二章大量使用定义和引用型引理，用来建立高斯过程、纳什均衡、李普希茨连续、微分平坦系统等基础概念。这里的定义主要服务后续章节调用，通常写法较短，先给数学对象，再给成立条件。引用型引理会保留来源，证明不再展开。这样的处理使第二章承担工具箱作用，不抢后续方法章节的重心。

方法章节中的定义应更加贴近本章问题。模范论文第三章先描述非接触人机交互中人类期望轨迹未知的场景，再给出问题 3.1，随后列出假设 3.1 和假设 3.2。假设之后紧跟一段解释，说明这些条件为什么符合物理系统约束，以及为什么是后续误差分析所需要的条件。这个顺序值得本文借鉴：先让读者知道问题来自哪里，再给出数学问题，然后用假设限定可分析范围。假设不能孤零零地出现，也不能写成没有物理含义的技术条件。

引理通常承担连接已有理论和本章结论的作用。模范论文第三章的人类期望轨迹误差分析不是直接给出大定理，而是先借助第二章高斯过程回归的误差界，再通过引理 3.1 推出期望轨迹估计误差界。第四章也先用引理说明代价函数在均衡策略下有界，再进一步给出控制策略跟踪性能相关定理。本文后续处理合作博弈、力位协同和安全仲裁时，也应让引理承担中间桥梁功能。例如，可以用引理说明权重区间不变、增益表有界、残差扰动可界定，再由定理给出闭环有界性或性能界。

定理应放在本章真正需要证明的核心性质上。模范论文第四章的定理用于说明控制策略的跟踪性能， 第五章的定理用于说明粘性解存在性和安全不变集条件。这些定理都直接对应章节贡献，不用于证明显而易见的工程事实。本文中，定理应优先服务三个问题：给定权重下的合作博弈反馈最优性，动态仲裁下的闭环有界性，安全投影或安全裕度设计对可行性的保证。若某个性质只是实现细节，例如滤波器输出被限幅到区间内，可以写成引理或性质说明，不宜包装成过大的定理。

证明部分应采用公式驱动的控制论文写法。模范论文的证明通常从“根据假设”“由引理”“结合公式”开始，随后给出不等式、收敛关系或反证步骤，最后用一句话回到定理结论。证明中很少插入解释性口号，也不会频繁打断公式推导。本文后续证明应避免把物理直觉写进证明主体；物理解释可以放在定理前的引入段或定理后的注中。证明中只保留必要的数学关系、条件调用和结论闭合。

“注”的使用也有明确边界。模范论文常在定理或算法后用注说明一般性、工程取值或保守性。例如，第五章安全性定理后说明安全项权重条件偏保守，实际工程中可取更小值。本文可借鉴这种写法，用注处理理论条件与工程实现之间的差异。注不应用来重复正文结论，也不应用来扩展新内容。比较合适的注包括：理论界限偏保守、某参数实际调节范围、某模型在真实柔性环境中的局部近似含义。

## 各章节的作用与段落功能

模范论文第一章承担定方向的作用。它不是直接进入公式，而是先从应用背景写到研究问题，再从研究现状写到本文动机。背景段落通常先描述机器人或人机交互的发展需求，再指出具体控制困难。研究现状段落按照研究方向组织，每个方向先介绍代表性方法，再分析不足，最后回到本文选择。研究内容与贡献部分先列出几个核心挑战，再把每个挑战对应到一项工作。本文绪论也应保持这种顺序。应用场景可以出现，但不要让场景之间互相抢主线；研究动机应始终回到人机协同、柔性接触、力位协调和安全仲裁。

模范论文第二章承担铺垫作用。它集中介绍后续章节会反复使用的理论工具，段落写法偏教材式，但仍然服务全文。每个小节一般先说明该工具为什么需要，再给出定义、公式和基本性质，最后简短说明其与后文方法的关系。本文第二章不宜写成控制理论大全，应只保留机器人任务空间建模、阻抗控制与柔性接触、合作博弈与帕累托最优控制、安全分析所需的基础。凡是后续章节不再调用的理论，不应占据过多篇幅。

模范论文第三章是一个较轻的算法章节。它的开头先指出一个具体困难，即人类期望轨迹未知会影响微分博弈策略求解。随后章节进入问题定义、假设、算法设计、误差分析和仿真验证。段落功能非常清楚：前两段提出困难，中间段建立数学关系，假设段限定分析条件，算法段说明如何求解，误差分析段给出理论保证，实验段验证估计效果。本文如果将某章写成仲裁方法章节，也应采用类似密度，不必在每个小环节都设置复杂定理，而应突出问题定义、特征构造、仲裁变量含义和实验可观测效果。

模范论文第四章是核心控制策略章节。它在第三章估计结果的基础上，处理非线性系统下的人机协同控制问题。章节结构从问题定义进入问题转化，再进入控制器设计、理论分析、仿真和实验。这里的段落更重视“前一节结果如何进入后一节”。例如，问题转化段解释为什么要进入微分平坦空间，控制器设计段说明如何求均衡策略，理论分析段证明代价函数有界和跟踪误差性质。本文的合作博弈力位控制章也应采用这种写法：先说明固定阻抗或固定权重的困难，再建立增广状态和代价函数，随后给出反馈律和稳定性分析，最后用仿真或实物结果验证。

模范论文第五章是安全扩展章节。它不是简单重复第四章，而是在已有协同控制策略基础上加入安全势能场和障碍物约束。段落推进方式是先说明安全问题为什么会破坏原有协同控制，再设计安全代价项，随后讨论问题转化、控制器求解、解的存在性和安全性。仿真部分按静态障碍物、安全测试场景和动态障碍物组织，实验部分再说明平台和结果。本文第五章若定位为系统集成与综合验证，应避免写成又一个全新理论章。更合适的段落作用是：说明第3章控制器和第4章仲裁器如何接入同一系统，说明集成后新增的安全投影和执行流程，说明消融实验如何验证每一层的必要性。

模范论文第六章的总结并不重新展开推导，而是按前面三项研究工作逐一回收贡献。每一段先说解决了什么问题，再说用了什么方法，最后说仿真或实验验证了什么性质。未来展望部分也保持克制，只提出方法可继续加强的方向。本文第六章也应避免重新堆公式或重复实验数据，应围绕合作博弈控制器、人机监督仲裁和系统集成验证三条主线总结。

从段落层面看，模范论文常见的自然段功能可以分为六类。章节开头段用于说明本章研究对象和与前文的关系；问题定义段用于把工程场景转化为变量、方程和待求目标；假设解释段用于说明数学条件的物理合理性；方法设计段用于把已有公式推进到控制律或算法；理论分析段用于通过引理和定理证明可解性、稳定性或误差界；实验分析段用于把图表中的现象解释回方法设计。后续修改本文时，每个自然段最好只承担其中一类功能。若一个段落同时承担背景、方法、指标、结果和结论，读者会感觉拥挤，也容易出现提示词式拼接。

本文可直接采用的章节段落节奏如下。每章开头用两段完成承接，第一段交代前一章留下的问题，第二段说明本章要解决的对象。问题描述小节用三到五段完成场景、变量、模型和控制目标。方法设计小节先解释设计动机，再给出公式和变量含义，随后说明在线实现流程。理论分析小节先用一段说明要证明的性质，再按引理、定理、证明、注的顺序推进。实验小节先写平台与参数，再写指标，然后按照图表顺序分析现象。小结部分用两段收束，第一段总结方法和理论，第二段总结实验结论并引出下一章。

需要特别注意的是，模范论文的分点多出现在研究贡献、算法流程和实验分组处，普通论述并不频繁分点。本文后续修改也应保持这个边界。能写成连续段落的内容，尽量写成连续段落；确实需要分点时，每一点应有明确同级关系，并且不要在分点内部继续套分点。这样既符合硕士论文的正式体例，也能减少人工智能生成文本常见的条目化痕迹。
